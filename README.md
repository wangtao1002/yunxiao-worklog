# 云效工时统计

在阿里云云效（Projex）里一键把「工时」算出来：列表页自动合计、日历热力图、团队对比、一键导出日报周报，全部在本地浏览器里完成。

> 版本 0.1.7 · Chrome 114+ · Manifest V3 · 纯原生 JS · 无构建 · 零依赖 · 不上传任何数据

---

## 为什么需要它

云效自带工时能力，但**在很多组织里它是空的**。

我们实测了自己的组织（见 `docs/API-RESEARCH.md` 第 6 节）：

- 项目「工时」模块（`/projex/project/{id}/inventory`）显示 **预估 0h / 登记 0h / 实登记人数 0**——
  因为团队根本没用云效原生的「工时登记」功能，原生工时统计页和度量报表永远是 0。
- 真实工时其实记在**自定义字段**上（本组织是「预计工时」「实际工时」两个 float 字段）。
  云效不会把自定义字段当工时来统计，于是这些数字散落在几百行列表里，只能人工数。
- 大家保存的筛选视图里，日期条件全是**写死**的，最久的一个还停在 9 个月前，
  打开就是一堆过期数据。

结果就是：月底要报工时，得把列表导出成 Excel 再自己拉公式。

这个插件干的就是这件事——**自动认出你们组织的工时字段，把散落的数字实时合计出来**。
字段 id 是运行时探测的，不是写死的，所以换一个组织、换一套字段名也能用。

## 功能

| 功能 | 说明 |
|---|---|
| **列表页合计条** | 工作项列表页右下角一个可拖拽的紧凑浮标，实时显示当前列表的条数与工时合计；可折叠成小圆点，位置会记住。列表超过 800 条时改为「点击才统计」，不自动翻页。 |
| **统计面板** | `Alt+H` 呼出。6 个概览卡：任务数 / 预计工时 / 实际工时 / 偏差 / 日均工时 / 逾期率。 |
| **日历热力图** | 按周排列（周一起），颜色深浅代表当日工时；工作日不足「每日标准工时」的格子会高亮描边，一眼看出哪天漏记了。点某一天可把明细表筛到那天。 |
| **分组统计** | 按项目 / 类别 / 状态 / 成员四个维度切换，横向条形图 + 数值，前 15 项 + 其余折叠。 |
| **团队对比** | 把同事加进通讯录后可分人出数（受云效权限限制，见常见问题）。 |
| **导出日报周报** | 一键复制 Markdown：概要行 + 按项目分组的汇总表 + **每个项目下的任务清单**（编号、标题、状态、工时），直接贴进日报周报或绩效自评。也可导出 CSV（带 BOM，Excel 打开不乱码，含公式注入防护）。 |
| **未填预计工时告警** | 统计范围里没填「预计工时」的任务会被**标红并置顶**，概览多一张「未填预计」卡（可点击只看这些），上方还有一条警示说明本区间漏了几条；列表页合计条也会多一个红色的「未填预计 N 条」。「预计工时」字段没识别出来时整套提醒自动关闭（那时全表都是 0，提醒只会是误报）；已取消的任务不提醒。可在设置页关掉。 |
| **批量补填工时** | 明细表里「预计」「实际」两列都可直接编辑（哪一列的字段没识别出来就自动降级为只读），支持「按预计工时一键填充」——按钮会实时显示**当前筛选下会影响几条**，不会碰到你筛掉的行。**默认只预演（dry-run）不写云效**，见下方安全说明。 |

## 安装

### 方式一：开发者模式加载（现在就能用）

1. 下载 / clone 本仓库到本地任意目录。
2. 打开 Chrome，地址栏输入 `chrome://extensions`。
3. 右上角打开「**开发者模式**」。
4. 点「**加载已解压的扩展程序**」，选择本仓库根目录（含 `manifest.json` 的那一层）。
5. 打开 <https://devops.aliyun.com/projex/workitem>，页面底部出现合计条即为成功。

> 升级：`git pull` 之后回到 `chrome://extensions` 点插件卡片上的刷新按钮，再刷新云效页面。

<https://cdn.jsdelivr.net/gh/wangtao1002/yunxiao-worklog@main/yunxiao-worklog.user.js>

## 使用

### 打开面板

- 快捷键 **`Alt+H`**（在输入框、文本域、富文本里按不会触发）。
- 或点浏览器工具栏上的插件图标。
- 或点列表页合计条右侧的「详细统计」。

不在云效页面时点图标，会直接帮你打开云效工作项列表页。

### 时间范围

预设：今天 / 昨天 / 本周 / 上周 / 本月 / 上月 / 近 7 天 / 近 30 天（周一为一周之始），
也可以用两个日期框自定义。默认口径在设置页里改。

### 归集口径（重要）

一个任务的工时要算在哪一天，取决于你选的口径：

| 口径 | 含义 | 什么时候用 |
|---|---|---|
| **计划完成时间**（默认） | 按任务的「计划完成时间」字段归集 | 日常排期、看这周计划了多少工时 |
| **实际完成时间** | 按任务真实完成的时间戳（`finishTime`）归集 | 复盘实际产出、写周报 |
| **计划开始时间** | 按「计划开始时间」字段归集 | 关注投入起点、排产 |

⚠️ 选「**实际完成时间**」时，云效侧没有可以直接筛的字段，插件的做法是
**按计划完成时间拉一个前后各扩 90 天的更宽区间，再在本地按实际完成时间过滤**。
所以区间外完成的任务可能统计不全，面板上会有对应提示。

其余口径都是云效服务端直接筛的，数据完整。

### 成员范围

- 默认「只看我」。
- 点「**+ 成员**」从通讯录里多选。
- 通讯录是**本地慢慢攒**出来的：点「从当前视图导入同事」，
  插件会扫当前页工作项的负责人，把人写进本地通讯录（云效没有可用的成员搜索接口，只能这么来）。
- 通讯录可以在设置页里逐个删除。

### 写入模式的安全说明

「预计」「实际」两列都可编辑，实际列还可批量填充，但插件对**写回云效**这件事非常保守
（「写入模式」这一个开关同时管着这两个字段的写回）：

1. **首次使用默认是「只读预演（dry-run）」**——改多少条都不会真的发写请求，
   只会告诉你「本来会把 A 改成 B」。要真写，得去设置页手动打开「允许写回云效」。
2. 真写之前会弹确认框，**逐条列出 `编号 + 标题 + 字段 + 旧值 → 新值`**，你能看清每一条再点确定；
   确认框标题会写明本次到底要写哪几个字段（如「写回云效：预计工时 / 实际工时」）。
3. 写之前先读一次当前值：**值没变的直接跳过**，不做无谓写入。
4. 写完**再读一次复核**，值对不上就报失败，绝不静默成功。
5. 失败的条目保留在表里，可以单独重试，不影响其它条目。

> 云效的字段写入端点是从其前端 bundle 里扫出来的（见 `docs/API-RESEARCH.md` 第 5 节），
> 官方没有公开文档。这正是插件默认 dry-run、并且每次都做写后复核的原因。
> **建议先拿一条无关紧要的任务试一次，确认没问题再批量用。**

## 常见问题

<details>
<summary><b>字段没识别出来 / 显示工时全是 0，怎么办？</b></summary>

插件靠字段名正则去认工时字段（`float / number` 类型 + 名字里同时含「预计/预估/计划…」和「工时/小时」之类的词）。
如果你们组织的字段叫「研发耗时」「投入人天」这种插件猜不到的名字，就会识别失败。

按顺序排查：

1. 打开**设置页**（面板底部「打开设置」，或 `chrome://extensions` → 插件详情 → 扩展程序选项），
   看「字段映射」区域显示的探测结果。
2. 点「**重新探测**」再试一次。探测样本取的是你名下的第一个工作项，
   如果你账号下**一个工作项都没有**，探测必然失败——先去云效认领一个任务。
3. 还是不行就**手动指定**：在字段映射里直接填字段的 identifier。
   怎么拿到 identifier：打开任意工作项详情页 → F12 → Network → 找 `workitem/field/...` 请求 →
   在返回里搜你的字段中文名，同级的 `identifier` 就是。
   手动填过之后会被标记为 `manual`，自动探测**不会再覆盖**它。
4. 也可能是字段有值但**这批任务确实没填**——云效的接口对没值的字段是**整条不返回**，
   不是返回 0，插件按 0 计。可以先在云效列表页把工时列显示出来核对一下。
</details>

<details>
<summary><b>「未填预计」是怎么判的？为什么有的任务填了 0 也算未填？</b></summary>

判据只有一条：**预计工时 ≤ 0 且任务未取消**。

- 云效对没填的自定义字段是**整条不返回**，插件按 0 计，所以「字段没值」和「明确填了 0」在数值上没有区别 ——
  两种都得补一个真实数字，因此都算未填。鼠标悬停在那一格上会告诉你具体是哪一种。
- **已取消**的任务不提醒（取消掉的任务再补工时没有意义），也不计入分母。
- 「**预计工时**」字段没识别出来时，整套提醒会自动关闭。因为那时全表 est 都是 0，
  提醒出来就是整表标红，那是字段映射问题而不是漏填 —— 这种情况请看筛选区那条字段告警。
- 在明细表里把数字补上，红色和置顶会立刻消失（还没提交到云效之前也一样，方便你核对改了哪几条）。
- 整个提醒可以在设置页「未填预计工时提醒」里关掉。
</details>

<details>
<summary><b>团队模式下，为什么查不到某个同事的数据？</b></summary>

这是云效的权限边界，不是插件的 bug。实测结论（`docs/API-RESEARCH.md` 第 2.2 节）：

| 查询方式 | 结果 |
|---|---|
| 在「我的空间」里查别人的任务 | ❌ 恒为 0 条 |
| 在「**那个人的空间**」里查那个人的任务 | ✅ 有数据 |
| 按组织维度查全员 | ❌ 恒为 0 条 |

所以插件是**按人循环、每人一次请求**去拉的。查不到通常是这几种情况：

- 那个人的 userId 没进通讯录（先用「从当前视图导入同事」导一次）。
- 你的账号对那个人的项目**没有查看权限**——云效会返回 0 条，插件无从分辨，只能显示 0。
- 那个人是外部成员 / 已离职停用。
- 那个人所在的时间区间内确实没有任务。

单个成员拉取失败**不会拖垮整体**：那一行会显示「加载失败（原因）」，其余人照常统计。
</details>

<details>
<summary><b>数字准不准？和云效页面对得上吗？</b></summary>

对得上，但要注意口径：

- 插件读的就是云效返回的**原始字段值**，不做任何换算和四舍五入（除了显示时最多保留一位小数）。
  合计条的数字可以直接和列表页的工时列逐行核对。
- 一个任务的工时**整体计入它的归集日**，不做跨天平摊。所以日历热力图上某天 24h 是正常的
  （那天有一个 24h 的任务，或者多个任务的计划完成日都压在那天）。
- 设置里「统计时排除已取消」默认开启——状态名里含「取消」的任务不计入。这会和云效页面的原始条数对不上，属预期。
- 云效里的「**预计工时汇总 / 实际工时汇总**」（`sum*` 开头的字段）是父子任务的只读 rollup，
  插件**故意排除**了它们，否则父任务和子任务的工时会被重复计算。
- 逾期率的判定**只认云效原生的「实际完成时间」，不看状态名**：
  - 有实际完成时间 → 看「实际完成 > 计划完成」；
  - 没有实际完成时间 → 看「现在 > 计划完成日 23:59:59」。

  这一条很关键：状态叫「**开发完成**」的任务，云效并没有给它实际完成时间，
  它其实还没结束（云效自己在列表里也照样标它「逾期N天」）。
  如果按状态名里有没有「完成」两个字来判，逾期率会被严重低报——
  实测同一批数据，按状态名判是 3.8%，按实际完成时间判是 69.2%，
  而后者与云效页面自己打的「逾期」标签数量完全一致。
  各家企业的状态名叫法不同，所以插件只信这个原生字段。
- 没有计划完成时间的任务、以及已取消的任务，都不参与逾期计算（既不算分子也不算分母）。
- 单次拉取有分页安全阀（最多 20 页 × 200 条）。碰到超大区间会标注「结果被截断」，缩小时间范围即可。
</details>

<details>
<summary><b>会不会把我的云效数据传到别的地方？</b></summary>

不会。所有请求只发往 `devops.aliyun.com`，用的是你浏览器里**已有的登录态**；
所有设置、通讯录与身份缓存只存在本机 `chrome.storage.local`。没有服务器、没有埋点、没有第三方 SDK。
详见 [PRIVACY.md](./PRIVACY.md)。
</details>

<details>
<summary><b>页面上什么都没出现？</b></summary>

1. 确认当前是 `https://devops.aliyun.com/` 下的页面，且已登录（未登录时面板会明确提示，不会白屏）。
2. 刚装完插件时，已经打开的云效标签页里还没注入脚本——**刷新一下页面**。
3. 设置页里「显示列表页合计条」可能被关掉了。
4. 合计条只在工作项列表页（`/projex/workitem`、`/projex/project/*/task|req|bug|workitem`）注入，详情页没有。
5. 插件对云效本身是「只读寄生」：任何异常只会在控制台 `console.warn`，不会弹窗、也不会影响云效正常使用。
   排查时可以打开 F12 控制台搜 `YXWT`。
</details>

## 隐私

**一句话：不收集、不上传、不共享任何数据。**

- 所有网络请求只发往 `devops.aliyun.com`，且只使用你浏览器已有的登录 Cookie，插件不接触你的账号密码。
- 设置、字段映射缓存、通讯录、本人身份缓存与成员选择只写进 `chrome.storage.local`，只在本机，卸载即消失。
- 界面上不加载任何远程资源（同事头像也用本地首字母占位块，不去请求阿里的头像 CDN）。
- 没有分析埋点、没有远程配置、没有第三方 SDK、没有远程代码。
- 权限只申请了 `storage` 和 `https://devops.aliyun.com/*`，没有 `<all_urls>`。

完整声明见 [PRIVACY.md](./PRIVACY.md)（中英双语）。

## 开发约定

- 纯原生 JS，**无构建、无 npm、无 CDN**，clone 下来直接 load unpacked。
- content script 模块一律 IIFE 挂到 `window.YXWT` 命名空间，加载顺序见上表，**依赖只能向前**。
- 组织 id / 用户 id / 字段 id **一律运行时探测**，代码里不允许出现写死的 id。
- 不用 `eval`，不用 `innerHTML` 拼接动态数据。
- 缩进 2 空格、单引号、带分号；注释中文，只在不显而易见处写。
- 改代码前先读 `docs/SPEC.md`（模块契约）和 `docs/API-RESEARCH.md`（接口实测）。
